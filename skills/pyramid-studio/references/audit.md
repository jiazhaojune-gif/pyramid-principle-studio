# 结构审稿

需要原稿才能审稿。先确定原稿的读者问题和文体；若问题来自推断要标明，推断不构成原文缺失背景的证据。

依次检查：
1. 主结论是否存在、是否回答读者问题、是否埋在细节后。
2. 原稿确有序言时才检查 SCQA；无序言的短文、片段或清单标为“不适用”，不判缺少背景为错误。
3. 下层是否回答上层引出的同一问题；引用断裂处。
4. 两个及以上同层观点是否回答同一父问题、承担同一角色；先判断共同角色再判断混组。明确范围才查遗漏，否则写“无法从材料确认穷尽性”。
5. 时间、结构、重要性或演绎排序是否有文本依据；列表位置不等于重要性顺序。

输出：总体判断（可直接使用/局部修改/需要重组）、中心观点原句、必要的开头检查、按影响排序的问题与修改建议。每项问题给原文位置或引句、破坏的逻辑关系和对应修法；没有实际问题就写“未发现需要调整的结构问题”，不要制造瑕疵。仅结构检查不证明事实正确，用户同时要求事实核对时分开列示。

学习例子可读 [audit/common-violations.md](audit/common-violations.md)，不得把例子里的事实或问题复制到当前诊断。
