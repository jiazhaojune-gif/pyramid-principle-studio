# 问题分析

1. 界定现状 R1、目标 R2、范围、时间，以及引发差距的事件。目标未知就标注待确定，不编数字。分清用户是在找方案、验证方案、选择方案还是执行方案。
2. 选择与领域材料相符的结构：流程/组成拆解、指标关系、可能原因分类。缺领域信息时先列需确认的结构，不把通用树声称为已穷尽。
3. 把可能原因列为假设，每项写“需什么证据、如何确认或排除”。同时寻找反证；用假设指导调查，不能只收集支持答案的材料。
4. 对已验证原因形成方案；比较时使用用户目标相关的共同标准，明确成本、风险、约束与缺失数据。没有证据时只给条件性选择，不下确定诊断。
5. 写成“建议/发现—理由—证据”的金字塔；调查顺序不必是报告顺序。

默认交付：问题界定；假设与验证表；现有证据能支持的判断；仍需资料；若用户要建议，再给有条件的行动选项。
