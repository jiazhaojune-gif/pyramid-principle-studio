# 第8章 界定问题

## 何时用这章
- 接手一个复杂问题要写分析报告/咨询建议书，先要搞清"真正的问题是什么"时
- 序言不知道怎么写、冲突找不准时——界定问题框架就是S-C-Q的生成器
- 客户/老板的问题表述模糊（"业绩不行，你看看怎么办"），需要还原成可回答的疑问时

## 核心框架
**问题=差距**：判断问题是否存在，看经过努力得到的结果与希望得到的结果之间有没有差距。

**连续分析法**（序列分析）的5连问：
1. 是否有/是否可能有问题（或机会）？
2. 问题出在哪里？
3. 为什么会出现问题（根源、原因）？
4. 我们能做什么？
5. 我们应该做什么？

前2问的答案构成文章**序言**，第3问是找原因，第4、5问的答案构成金字塔中的**思想、观点、论点**。

**界定问题框架4要素**（像戏剧术语一样展开）：
| 要素 | 含义 | 写作要点 |
|------|------|---------|
| 切入点/序幕 | 特定时刻、地点的结构与流程（舞台布景） | 设想简单、描述简短，序言时再展开 |
| 困扰/困惑 | 威胁稳定背景的事件（现在/即将/未来发生） | 外部原因、内部原因、近期认识到的其他原因 |
| R1（非期望结果/现状） | 困扰导致的、你不喜欢的结果；也可能是未抓住的机会 | 可能不止一个，用简短文字列出 |
| R2（期望结果/目标） | 你希望结构或流程产生的结果 | 尽可能具体（数字或具体结果）；写不出就先写希望达到的状态 |

完整展开时还有两个附加要素：**答案**（到目前为止针对问题已经采取的措施，如果采取了的话）和**疑问**（为了解决问题，必须做什么）——它们决定文章正文回答什么。

## 关键原则（每条=规则+一句话理由）
1. **从左到右再向下转成序言**：把框架图按阅读顺序展开，读者了解的**最终事实**作为冲突——界定问题做完，序言就自动成型
2. **先确认读者走到哪一步**：读者是不知道方案、不确定方案对不对、还是方案已失败——不同阶段的疑问完全不同，写错阶段就答非所问
3. **R1/R2在解决过程中可以变**：收集资料后可能要重新提炼描述——但各要素之间的相互关系始终占主导，框架不会散
4. **找不到困扰事件时直接跳到R1**：信息不充分时（尤其项目建议书），客户对现状的不满本身就是起点
5. **信息不足不硬写R2**：无法具体描述最终结果时，写下"问题解决后希望达到的状态"，把确定具体R2当作解决问题的第一步
6. **备选方案放在冲突之后，不罗列后否定**：读者会把罗列的方案误当作选择理由；采用C方案的原因不是A、B不好，而是C行之有效
7. **多种界定=多个戏剧层级**：问题可扩展为3个层级（每层有自己的R1、R2、解决方案），写作时只把读者已知的最终事实作冲突，历史层级压缩进背景

**7种读者状况→疑问**（前3种最常见）：
1. 不知道如何将R1转化为R2 → "我们应该做什么？"（关键词：**改变**；若教人做事则关键词是**步骤**）
2. 知道方案但不确定是否正确 → "我们是否应该这样做？"
3. 知道正确方案但不知如何实施 → "我们应该如何做？"
4. 方案已实施但行不通 → 追溯历史后发现真正问题 → "我们应该做什么？"
5. 有几个方案不知选哪个 → "应该选择哪种方案？"
6. 知道R1但描述不出R2（战略咨询）→ "应该采用哪些战略？"（关键句=制订战略的步骤）
7. 知道R2但不确定是否处于R1（典型标杆比对）→ "我们存在问题吗？"

## 操作步骤（如适用）
**界定问题五步**：
1. 把问题展开成框架图（4要素、必要时多层）
2. 确定读者的解决方案处于哪一阶段（未提出/已提出/已接受/已失败）
3. 按7种状况提出适当的疑问
4. 检查序言是否说明了界定的问题（S=背景层级，C=读者已知的最终事实，Q=该阶段的疑问）
5. 检查金字塔是否回答了该疑问

**实战模板**（多方案选型）：S=我们存在问题 → C=我们有几种不同方案（各自影响投资回报）→ Q=选择哪个方案？→ 关键句按评估维度展开。

## 反模式（避免什么+为什么）
- **不问读者进度就动笔**：作者常犯的严重错误是没确认读者是否已采取行动——方案已失败的企业要的是"接下来做什么"，不是"该不该做"
- **R2含糊**：不说清目标就无法选择解决方案，也无法判断是否达成——"恢复正常"不是R2，"恢复10%的年增长"才是
- **只盯着负面R1**：困扰也可能带来未被发现的机会；R1可能是"错失的机会"而不只是"恶化的指标"
- **序幕写得太满**：结构和流程的描述在序幕阶段点到为止，展开细节是序言的事——开头就铺陈背景会淹没冲突
- **罗列备选方案再逐一否定**：显得"我其实没有立场"；方案对比应服务于"为什么C有效"，不是走过场
- **把困扰事件和R1混为一谈**：困扰是触发事件（新技术出现），R1才是它导致的结果（市场份额下降）——两者混淆会让冲突失去推进力
