# 第4章 序言的具体写法

## 何时用这章
- 写文章开头、演讲开场白、备忘录/报告/项目建议书的开篇时
- 读者"看了半天不知道你要干什么"、开头抓不住人时
- 为不同文体（指示、申请、咨询建议书、进度小结）套用标准序言模板时

## 核心框架
**S-C-Q-A 序言故事结构**（序言位于金字塔结构之外、塔尖之上）：
1. **背景（Situation）**：读者已知、无争议的事实，把读者锁定在特定时间和空间
2. **冲突（Complication）**：推动故事情节发展的因素——某种变化、问题或意外，让读者心里冒出"接下来会怎么样"
3. **疑问（Question）**：冲突自然引发的那个问题，全篇只能有一个初始疑问
4. **回答（Answer）**：即金字塔塔尖的中心思想

**为什么用讲故事形式**：读者头脑中塞满与主题无关的思想，只有被"未讲完的故事"制造悬念才能专注；先传递读者必然认可的信息（最好的故事是读者已经听过的故事），再呈现他可能不同意的内容。

**多数文章只回答4类疑问之一**：我们应该做什么？我们应该如何做？我们是否应该这样做？为什么会发生这种情况？

## 关键原则（每条=规则+一句话理由）
1. **背景必须是独立的、无争议的表述**：独立=无需其他句子解释其含义；无争议=读者必然理解并接受——这是序言能"站住"的前提；如果找不到这样的背景，要么主题选错了，要么时机不对
2. **冲突不是字面的问题**：它是让情节往前走、迫使读者提问的因素，通常都能归结为"接下来会怎么样"
3. **S、C、A三要素缺一不可，顺序可变**：变序塑造文风——标准式（S-C-A）平实、开门见山式（A-S-C）直接、突出忧虑式（C-S-A）施压、突出信心式（Q-S-C-A）先声夺人
4. **序言是提示不是告知**：不放读者需要求证才能接受的信息（包括图表）——序言只唤醒已知，论证留给正文
5. **初始疑问全篇唯一**：两个疑问必有关联（"是否进入市场"+"如何进入"实为一个疑问），找不到初始疑问时用正文素材倒推——素材之所以要写，是因为它能回答某个问题
6. **序言长度由读者需要决定**：通常2-3段，背景+冲突最多3-4段；与读者越熟可越短，短到一句话也行（"你在1月15日的信中问我……"），但再短都必须能唤起疑问
7. **关键句要点=回答新疑问+呈现框架**：列出要点让读者30秒了解全部思路，之后不会有意外内容，读与不读由读者决定；短文中要点直接作段落主题句并加粗
8. **关键句要点必须是完整的思想、完整的句子**：罗列名词（"背景""项目内容""具体收益"）只硬塞词汇不传信息，还可能暴露思想间缺乏逻辑关系
9. **每个关键句要点都要有自己的微型引言**：按简化版S-C-Q逐个引出；第一个要点的引言说明"此主题为何与全文相关"，后续要点的引言说明"此主题与前面主题如何相关"
10. **请求支持式只有3-4个标准理由**：问题刻不容缓；此方案能解决（或是最优方案）；方案收益超过成本；还有额外好处（若成立才写）

## 操作步骤（如适用）
**四种常见序言模式模板**：
1. **发出指示式**（告诉读者做某事）：S=我们打算做X / C=需要你们做Y / Q=如何做Y → 回答是步骤；疑问可隐含，但作者动笔前必须向自己明确写出
2. **请求支持式**（经费申请）：S=我们遇到问题 / C=已有解决方案、需要__经费 / Q=应该批准吗 → 关键句=3-4条标准理由
3. **解释做法式**（教读者解决问题）：S=必须做X（或你目前的系统是X）/ C=还未准备好（系统不能正常工作）/ Q=如何改进 → **动笔前在纸上列出"现状流程"与"正确流程"并排对比，两个流程的差异直接决定关键句要点**
4. **比较选择式**（多方案取舍）：S=我们希望做X / C=有几种执行方案 / Q=哪种最合理 → 首选围绕评估标准写关键句；若推荐方案并非每项标准都最优，则改为"选择C的原因+放弃A、B的原因"；注意围绕替代目标而非替代方案组织

**咨询类两种变体**：
- 项目建议书：S=你遇到一个问题 / C=你决定请第三方解决 / Q=你是合适的第三方吗 → 关键句四件套：我们理解问题、我们有合理方法、我们有丰富经验、项目安排合理
- 项目进度小结：S=我们告诉过你X / C=你要求调查Y，已完成 / Q=发现了什么 → 回答陈述发现

## 反模式（避免什么+为什么）
- **序言里放图表**：图表是需要求证的信息，出现即说明你过多强调了已知事实
- **序言超长**：超过3-4段背景冲突，读者会问"你还需要多少字提醒我已经知道的事"？
- **要点只列名词**："背景、方法、内容、收益"式目录既不传思想也不成逻辑，浪费读者时间
- **用"背景""介绍"当章节标题**：与其他标题不在同一抽象层次，无法形成归纳或演绎关系
- **不对比两个流程就写"解释做法"文章**：自以为熟悉领域就凭印象写，遗漏关键因素的概率极大
- **迎合"再提几个替代方案"的字面要求**：若问题界定正确，方案要么能解决要么不能，不存在替代方案——管理者真正要的是"无法彻底解决时给可尝试的方案"，写替代目标而非替代方案
- **让读者自行摸索着进入主题**：不先讲他认可的故事，读者摆脱不了脑中杂念，读一页半也一个字没进脑子
